# Triplogue

Triplogue는 여행 사진을 업로드하면 촬영 시간과 위치 정보를 읽어 날짜별, 장소별로 자동 정리하고, 이를 Sweetbook 포토북 주문 흐름으로 연결하는 웹앱입니다.

핵심 경험은 아래와 같습니다.
- 여행 사진을 올립니다.
- 앱이 EXIF의 촬영 시간과 GPS 정보를 우선 읽습니다.
- 사진을 날짜별, 장소별 챕터로 자동 그룹핑합니다.
- 위치 정보가 없는 사진은 수동 태깅으로 보완합니다.
- 정리된 여행 기록을 포토북 초안과 주문 흐름으로 연결합니다.

## 가장 빠른 재현 경로

리뷰어나 발표자는 아래 순서로 보면 됩니다.

1. 샘플 여행 초안을 불러옵니다.
2. 검토 화면에서 위치 태그 보정과 챕터 재정렬을 확인합니다.
3. 포토북 미리보기에서 패턴 3종을 비교합니다.
4. 체크아웃에서 테스트 책 생성과 주문 추적을 확인합니다.

실제 사진 업로드가 없어도 이 경로만 따라가면 `업로드 -> 검토 -> 미리보기 -> 주문 -> 웹훅 운영`의 핵심 흐름을 바로 볼 수 있습니다.

## 현재 MVP 방향

이번 MVP는 아래 한 문장에 집중합니다.

`여행 사진첩을 최소한의 수정만으로 포토북 초안까지 빠르게 만드는 경험`

특히 데모와 리뷰에서는 `샘플 여행 초안`이 기본 시작점입니다.  
샘플 데이터로 전체 흐름을 먼저 보여주고, 실제 사진 업로드는 동일한 경로를 검증하는 보조 수단으로 둡니다.

현재까지 잡아둔 큰 덩어리는 다음과 같습니다.
- 랜딩과 서비스 방향 제시
- 샘플 여행 초안과 빠른 재현 경로
- 사진 업로드 및 인입 흐름
- 자동 그룹핑 검토 화면
- 포토북 미리보기 화면
- Sweetbook 실제 상품 규격 기반 페이지/가격 반영
- 주문 연동용 체크아웃 골격
- Sweetbook API 및 웹훅 연동용 백엔드 기반
- 웹훅 운영 패널 초안 (`/ops/webhooks`)

## 사용자 준비 사항

개발과 테스트를 위해 필요한 것은 많지 않습니다.

1. Sweetbook 파트너 계정과 Sandbox API Key
2. `.env.example`을 복사해 만든 `.env`
3. 갤럭시 데모 사진용 위치 태그 설정

갤럭시 사진 테스트는 아래 설정을 권장합니다.

`카메라 > 설정 > 위치 태그(Location tags)`를 켜 두면 여행 사진의 GPS 메타데이터가 더 잘 유지됩니다.

위치 정보가 없는 사진은 업로드 후 수동으로 장소 태그를 붙이는 흐름으로 처리합니다.

## 환경 변수

```bash
cp .env.example .env
```

```env
SWEETBOOK_API_KEY=
SWEETBOOK_ENV=sandbox
SWEETBOOK_WEBHOOK_SECRET=
```

## 로컬 실행

```bash
npm install --ignore-scripts
npm run dev
```

실행 후 브라우저에서 [http://localhost:3000](http://localhost:3000)을 열면 됩니다.

## 빠른 데모 재현

리뷰어나 발표자가 가장 빨리 전체 흐름을 확인하는 방법은 샘플 여행 초안을 먼저 불러오는 것입니다.

1. 홈(`/`) 또는 업로드(`/trips/new`)에서 `샘플 초안으로 검토 시작` 버튼을 누릅니다.
2. 세션에 데모용 여행 초안이 저장되고 검토 화면으로 이동합니다.
3. 이후 `검토 -> 미리보기 -> 주문 -> 웹훅 운영` 순서로 그대로 진행합니다.

샘플 초안에는 아래 상태가 함께 들어 있습니다.
- 위치가 자동 정리된 사진
- 시간대 기준으로 장소를 보완한 사진
- 수동 태깅이 필요한 사진 1장
- 지도 카드 연출에 쓸 수 있는 GPS 좌표

실사진 검증이 필요하면 같은 업로드 화면에서 바로 파일을 올려 실제 EXIF 기반 흐름도 확인할 수 있습니다.

첫 진입 후에는 랜딩에서 `샘플 여행 초안 불러오기` 또는 업로드 시작 경로를 먼저 확인하면 가장 빠릅니다.

## 운영 보조 화면

현재 MVP에는 운영 확인용 화면도 포함되어 있습니다.

- `/ops/webhooks`: Sweetbook 웹훅 등록, 테스트 전송, delivery 이력 조회, 수신 로그 확인
- `/checkout`: 테스트 책 생성, 주문 요청, orderUid 또는 bookUid 기준 수신 추적
- `/api/sweetbook/status`: API Key, Book Specs 연결, 웹훅 설정 여부를 점검하는 상태 API

홈, 업로드, 운영 화면 우측에는 위 상태 API를 읽는 `백엔드 상태` 카드가 들어 있습니다.
처음 실행할 때는 이 카드부터 보고 아래 항목이 살아 있는지 확인하면 됩니다.
- Sweetbook 환경이 sandbox인지
- API Key가 서버에 설정되어 있는지
- `book-specs`가 실제로 조회되는지
- 웹훅 설정이 이미 연결되어 있는지

이 화면은 운영 전환 전에 아래 항목을 빠르게 검증하기 위한 용도입니다.
- 웹훅 URL 등록 상태
- 최초 응답의 `secretKey` 보관 여부
- 테스트 전송 성공/실패 응답
- 최근 실패 delivery 추적
- 실제 수신 receipt와 delivery 이력의 대응 관계
- 주문 직후 checkout에서 바로 상태를 추적할 수 있는지
- checkout에서 얻은 `orderUid` 또는 `bookUid`를 `ops/webhooks`로 넘겨 같은 기준의 receipt 로그를 바로 이어서 보는지

샘플 초안을 불러온 뒤에는 위 화면을 통해 검토와 주문 추적까지 한 번에 이어서 보는 것을 권장합니다.
