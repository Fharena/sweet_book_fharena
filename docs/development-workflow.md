# 개발 진행 원칙

이 프로젝트는 짧은 시간 안에 완성도를 끌어올리기 위해 아래 원칙으로 진행합니다.

## 작업 방식

- 가능한 경우 서브에이전트를 사용해 병렬로 작업한다.
- 작업 단위는 너무 잘게 쪼개지 않고 큰 기능 덩어리로 나눈다.
- 프론트엔드와 백엔드는 책임 경계를 분리하되, 사용자가 바로 확인할 수 있는 흐름 중심으로 우선 구현한다.
- 결정이 필요한 지점이 아니면 멈추지 않고 계속 진행한다.

## PR 원칙

- 중간중간 Draft PR을 먼저 열어 진행 상황을 누적한다.
- PR 설명은 기본적으로 한글로 작성한다.
- PR 본문에는 현재 상태, 확인한 사실, 남은 작업을 함께 적는다.

## 이슈 기록 원칙

- 크리티컬한 이슈는 별도 문서로 남긴다.
- 기록 구조는 `문제 / 영향 / 원인 가설 / 대응 / 남은 리스크`를 따른다.
