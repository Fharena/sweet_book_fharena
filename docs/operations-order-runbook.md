# 운영/주문 확인 런북

이 문서는 제출 직전과 데모 직전에 실제로 무엇을 확인해야 하는지 한 번에 정리한 런북입니다.  
목적은 두 가지입니다.

1. 여행 포토북이 실제로 끝까지 만들어지는지 확인한다.
2. 주문과 웹훅 상태를 운영 관점에서 빠르게 해석할 수 있게 한다.

## 언제 읽는가

- 브라우저 수동 검증을 시작하기 전
- 테스트 책 생성 후 주문을 요청하기 전
- 웹훅 테스트 전송이나 delivery 확인이 필요할 때
- 제출 직전에 누락이 없는지 마지막으로 점검할 때

## 최소 준비물

- `.env`에 설정된 `SWEETBOOK_API_KEY`
- `SWEETBOOK_ENV`
- `SWEETBOOK_WEBHOOK_SECRET`
- 샘플 여행 초안 또는 실제 여행 사진
- 브라우저에서 열려 있는 Triplogue

## 권장 확인 순서

### 0. 샘플 여행 초안

- 홈(`/`) 또는 업로드(`/trips/new`)에서 `샘플 초안으로 검토 시작` 버튼을 누른다.
- 실제 사진 업로드 없이도 검토, 미리보기, 주문, 웹훅 운영까지 이어지는지 확인한다.
- 리뷰어 기준 가장 빠른 재현 경로가 이 단계에서 막히지 않는지 본다.

### 1. 업로드

- 여행 사진을 업로드한다.
- 사진 개수와 총 용량이 상식적인지 본다.
- 위치 태그가 살아 있는 사진과 수동 태깅이 필요한 사진이 함께 보이는지 확인한다.

### 2. 검토

- 자동으로 묶인 챕터가 날짜와 장소 기준으로 자연스럽게 보이는지 확인한다.
- 위치 정보가 없는 사진을 선택해 수동 태그를 적용한다.
- 태그 적용 후 챕터 수와 수동 보정 개수가 갱신되는지 확인한다.

### 3. 미리보기

- 선택한 디자인 패턴이 실제 draft에 반영되는지 확인한다.
- 예상 페이지 수와 예상 금액이 사진 수에 맞게 바뀌는지 확인한다.
- 챕터별 사진 묶음이 반복되지 않고 각 장면에 맞게 보이는지 확인한다.

### 4. 책 생성

- 테스트 책 생성 버튼을 눌러 `bookUid`가 만들어지는지 확인한다.
- 생성 결과에 테마와 조립 단계 수가 표시되는지 확인한다.
- 최종화 상태가 주문 전제 조건으로 유지되는지 확인한다.

### 5. 주문

- 배송지와 수량을 입력한다.
- `bookUid`가 비어 있지 않은지 다시 확인한다.
- 주문 요청 후 응답에 `orderUid`, 상태, 차감 금액이 보이는지 확인한다.
- checkout의 주문 추적 카드에서 최근 이벤트와 마지막 동기화 시각이 보이는지 확인한다.
- 필요하면 `지금 새로고침`으로 receipt가 바로 들어오는지 다시 확인한다.

### 6. 웹훅 운영

- 웹훅 설정을 저장하고 최초 응답의 `secretKey`를 바로 보관한다.
- 테스트 이벤트를 전송하고 delivery가 하나 생성되는지 확인한다.
- 수신 로그에서 `deliveryUid`, `receiptUid`, 검증 상태를 함께 본다.
- 실패 건과 중복 건이 있으면 같은 deliveryUid 기준으로 묶여 보이는지 확인한다.

## 자주 만나는 문제

### `bookUid`가 없어서 주문이 안 된다

- 테스트 책 생성을 먼저 실행해야 한다.
- 생성 후 페이지를 새로 고치지 않아도 sessionStorage에 bookUid가 남는지 확인한다.

### 주문이 400으로 실패한다

- shipping 필수 항목이 빠졌는지 먼저 확인한다.
- `bookUid`가 실제로 최종화된 값인지 확인한다.
- 수량이 1에서 100 사이인지 확인한다.

### 웹훅이 계속 실패한다

- `SWEETBOOK_WEBHOOK_SECRET`가 설정되어 있는지 확인한다.
- 테스트 전송 응답과 수신 로그의 `verificationStatus`를 비교한다.
- delivery와 receipt가 둘 다 없으면 등록 URL부터 다시 확인한다.

### 수동 태깅 결과가 원하는 챕터로 안 묶인다

- 같은 사진 묶음에 적용했는지 확인한다.
- 라벨을 입력한 뒤 선택 사진에 다시 태그 적용을 눌렀는지 확인한다.
- 검토 후 미리보기로 돌아가 draft가 갱신됐는지 확인한다.

## 데모 시 체크 포인트

- 샘플 여행 초안만으로도 전체 흐름이 한 번에 보이는가
- 업로드에서 사진과 위치 정보를 읽는 흐름이 보이는가
- 검토에서 수동 보정이 빠르게 적용되는가
- 미리보기에서 패턴이 눈에 띄게 달라지는가
- 책 생성 후 주문까지 같은 draft가 이어지는가
- 웹훅 운영에서 실제 수신과 검증 상태를 설명할 수 있는가
