# 제출 체크리스트

제출 직전에 아래 항목을 순서대로 확인합니다.

## 산출물

- [ ] GitHub 저장소가 공개 상태이거나 제출 요구사항을 만족한다
- [ ] 최신 변경 사항이 원격 브랜치에 push 되어 있다
- [ ] Draft PR 또는 제출용 PR 링크가 준비되어 있다
- [ ] README에 프로젝트 소개와 실행 방법이 정리되어 있다
- [ ] 데모 스크립트가 문서로 준비되어 있다
- [ ] 운영/주문 확인 런북이 문서로 준비되어 있다

## 환경 변수

- [ ] `.env.example`이 저장소에 포함되어 있다
- [ ] 로컬 `.env`에 `SWEETBOOK_API_KEY`가 설정되어 있다
- [ ] `SWEETBOOK_ENV`가 `sandbox` 또는 제출용 값으로 맞춰져 있다
- [ ] `SWEETBOOK_WEBHOOK_SECRET`가 설정되어 있다
- [ ] 실제 비밀값이 README, PR 본문, 커밋 메시지에 노출되지 않았다

## 기능 확인

- [ ] 업로드 화면에서 사진을 올릴 수 있다
- [ ] EXIF 촬영 시간과 GPS 기반 자동 그룹핑이 동작한다
- [ ] 위치 정보가 없는 사진을 수동 태깅으로 보정할 수 있다
- [ ] 검토 화면에서 보정 결과가 draft에 반영된다
- [ ] 미리보기 화면에서 디자인 패턴과 예상 페이지 수를 확인할 수 있다
- [ ] 테스트 책 생성이 가능하다
- [ ] 책 생성 후 최종화 상태를 확인할 수 있다
- [ ] 주문 단계로 배송지와 수량을 넘길 수 있다
- [ ] checkout에서 orderUid 또는 bookUid 기준 수신 로그를 확인할 수 있다
- [ ] 웹훅 운영 화면에서 설정, 테스트 전송, 수신 로그를 확인할 수 있다

## 검증

- [ ] `npm run lint`가 통과한다
- [ ] `tsc --noEmit`이 통과한다
- [ ] 로컬 브라우저에서 `업로드 -> 검토 -> 미리보기 -> 주문 -> 웹훅 운영` 순서를 한 번 이상 확인했다
- [ ] 샘플 사진으로 실제 데모 흐름을 다시 재현해 보았다
- [ ] 운영/주문 확인 런북의 체크 항목을 실제로 한 번 따라가 보았다

## 제출 메모

- [ ] PR 본문이 한글로 작성되어 있다
- [ ] 크리티컬 이슈가 있다면 `docs/critical-issues.md`에 정리되어 있다
- [ ] 발표자가 읽을 5분 데모 스크립트가 준비되어 있다
